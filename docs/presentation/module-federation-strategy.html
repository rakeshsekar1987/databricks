What is Module Federation?

Webpack 5 feature for micro-frontend architecture

🏠 Host Application (Shell)

The main container that dynamically loads remote modules at runtime. Provides:

  • Global navigation and layout
  • Authentication/authorization
  • Routing between modules
  • Shared dependency management

📦 Remote Modules

Independent applications that expose components to be consumed by the host:

  • Deployed independently
  • Own dependencies & versions
  • Loaded on-demand
  • Can be updated without host rebuild
// Shell webpack.config.js - Host configuration
new ModuleFederationPlugin({
  name: 'shell',
  remotes: {
    taxReporting: 'taxReporting@https://cdn.example.com/tax/remoteEntry.js',
    regReporting: 'regReporting@https://cdn.example.com/reg/remoteEntry.js',
  },
  shared: { react: { singleton: true } }
})

  name: 'taxReporting',

    'ag-grid-community': {
      singleton: false, // NOT singleton - allows different versions

    }
  }
})

Module Registry Service

{
  "modules": {
    "taxReporting": {
      "remoteEntry": "https://cdn/tax/v3.0.1/remoteEntry.js",
      "agGridVersion": "29.3.0",
      "version": "3.0.1"
    },
    "regReporting": {
      "remoteEntry": "https://cdn/reg/v2.1.0/remoteEntry.js",
      "agGridVersion": "31.0.0",
      "version": "2.1.0"
    }
  }
}

Shell Dynamic Loading

// Shell loads modules at runtime
const manifest = await fetch('/api/module-manifest');
const { modules } = await manifest.json();

// Load Tax Reporting with AG Grid v29
const TaxApp = await loadRemote(
  modules.taxReporting.remoteEntry,
  './App'
);

// Render the remote component
<Suspense fallback={<Loading />}>
  <TaxApp />
</Suspense>
Benefits: Update module versions without redeploying the Shell. A/B testing different module versions. Instant rollback by updating registry.
